# FixFlow — Member 1 Team Contract & API Documentation

**Module**: Core Domain, User Management & Authentication  
**Author**: Member 1  
**Target Audience**: Member 2 (Ticket Management), Member 3 (Assignment, Priority, SLA), Member 4 (Reports, Notifications, QA)

---

## 1. Overview & Architectural Role
Member 1 provides the core foundation of FixFlow:
- User domain entity and life-cycle management.
- System roles (`USER`, `TECHNICIAN`, `ADMIN`) and account statuses (`ACTIVE`, `INACTIVE`).
- Secure authentication and password hashing (PBKDF2-HMAC-SHA256).
- User validation rules and boundary limits.
- Repository abstraction (`UserRepository` / `InMemoryUserRepository`).
- Custom domain exceptions.

## 3. Domain Model: `User`
Package: `com.fixflow.model.User`

### Fields & Types
| Field | Type | Description |
|---|---|---|
| `id` | `Long` | Unique identifier generated by repository |
| `fullName` | `String` | User's full name (2–50 chars) |
| `username` | `String` | Unique username (3–20 chars, alphanumeric + underscores) |
| `email` | `String` | Unique email address (case-insensitive) |
| `passwordHash` | `String` | PBKDF2 encoded hash (never exposed as plain-text) |
| `role` | `Role` | `USER`, `TECHNICIAN`, or `ADMIN` |
| `status` | `UserStatus` | `ACTIVE` or `INACTIVE` |
| `createdAt` | `LocalDateTime` | Record creation timestamp |
| `updatedAt` | `LocalDateTime` | Record last modification timestamp |

### Key Methods
- `getId()`, `setId(Long id)`
- `getFullName()`, `setFullName(String fullName)`
- `getUsername()`, `setUsername(String username)`
- `getEmail()`, `setEmail(String email)`
- `getPasswordHash()`, `setPasswordHash(String passwordHash)`
- `getRole()`, `setRole(Role role)`
- `getStatus()`, `setStatus(UserStatus status)`
- `isActive()`: returns `true` if `status == UserStatus.ACTIVE`
- `getCreatedAt()`, `getUpdatedAt()`
- `User.builder()`: Builder pattern for convenient object instantiation.
- `toString()`: Sensitive `passwordHash` is protected and masked.

## 4. Exceptions Contract
Package: `com.fixflow.exception`

All exceptions extend `RuntimeException`.

| Exception | When Thrown |
|---|---|
| `ValidationException` | Input violates field validation or boundary rules |
| `UserNotFoundException` | User lookup by ID, username, or email fails |
| `UserAlreadyExistsException` | Username or email already registered |
| `AuthenticationException` | Invalid login credentials or inactive account |

## 5. Public Services Contract

### 5.1 `UserService`
Package: `com.fixflow.service.UserService`

#### Method: `registerUser`
```java
public User registerUser(String fullName, String username, String email, String rawPassword, Role role)
```
- **Inputs**:
  - `fullName`: String (2–50 chars)
  - `username`: String (3–20 chars, unique)
  - `email`: String (valid format, unique)
  - `rawPassword`: String (min 8 chars, 1 uppercase, 1 lowercase, 1 digit, 1 special char)
  - `role`: `Role` (`USER`, `TECHNICIAN`, `ADMIN`)
- **Output**: `User` (with generated ID and `UserStatus.ACTIVE`)
- **Throws**: `ValidationException`, `UserAlreadyExistsException`

#### Method: `getUserById`
```java
public User getUserById(Long id)
```
- **Output**: `User`
- **Throws**: `ValidationException` (if id is null), `UserNotFoundException`

#### Method: `getUserByUsername`
```java
public User getUserByUsername(String username)
```
- **Output**: `User`
- **Throws**: `ValidationException`, `UserNotFoundException`

#### Method: `getUserByEmail`
```java
public User getUserByEmail(String email)
```
- **Output**: `User`
- **Throws**: `ValidationException`, `UserNotFoundException`

#### Method: `updateUser`
```java
public User updateUser(Long id, String fullName, String username, String email, Role role)
```
- **Output**: Updated `User`
- **Throws**: `ValidationException`, `UserNotFoundException`, `UserAlreadyExistsException`

#### Method: `activateUser` / `deactivateUser`
```java
public void activateUser(Long id)
public void deactivateUser(Long id)
```
- **Throws**: `UserNotFoundException`

#### Method: `deleteUser`
```java
public void deleteUser(Long id)
```
- **Throws**: `UserNotFoundException`

#### Method: `listUsers`
```java
public List<User> listUsers()
```


## 6. Repository Abstraction: `UserRepository`
Package: `com.fixflow.repository.UserRepository`

```java
public interface UserRepository {
    Optional<User> findById(Long id);
    Optional<User> findByUsername(String username);
    Optional<User> findByEmail(String email);
    boolean existsByUsername(String username);
    boolean existsByEmail(String email);
    User save(User user);
    User update(User user);
    void delete(Long id);
    List<User> findAll();
    List<User> findByRole(Role role);
    void clear();
}
```
Implementation provided: `InMemoryUserRepository` (Thread-safe with defensive copying).

## 7. How Other Team Members Integrate

### For Member 2 (Ticket Management)
- In `Ticket.java`, reference `User reporter` (where `reporter.getRole() == Role.USER` or any user).
- To validate ticket creator existence, call `userService.getUserById(reporterId)`.

### For Member 3 (Assignment, Priority, SLA)
- In `TicketAssignment.java` or `AssignmentService`, retrieve available technicians using:
  ```java
  List<User> technicians = userService.getUsersByRole(Role.TECHNICIAN);
  ```
- Before assigning a ticket, ensure `technician.getStatus() == UserStatus.ACTIVE` via `technician.isActive()`.

### For Member 4 (Reports, Notifications & QA)
- For user activity reports, use `userService.listUsers()`.
- For notifications, obtain recipient email and name via `user.getEmail()` and `user.getFullName()`.
- For integration testing, instantiate `new InMemoryUserRepository()` or share repository instances.
